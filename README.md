# 吃饭 · cortico-world-eat

给 Coopanion 桌宠补上一件正经事：**吃饭**——顺便还有**种田**。

它给宠物一个饱食度、一个米仓、一个电饭煲，以及一块水稻田和一个水池。田里还会闹虫灾、来鸟群，可以立稻草人。主人直接在控制台的「厨房」「稻田」面板上加米、煮饭、吃饭、播种、浇水、施肥、收割、打水、立稻草人；桌宠用工具自己做同样的事。煮饭需要时间，饭好了会有 `eat.cooked`；饿了也不会只写在脸上——饱食度跨过新的阶段时，会有一条 `eat.hunger` 事件提醒，比如“有点饿了”。

水稻则安静得多：它按真实时间慢慢长，土壤越湿长得越快，浇水能立刻催一截；环境会时不时下雨，替你把田浇了、把水池补上；也会时不时闹虫、来鸟——鸟先吃虫，虫吃光了就啄稻穗，立个稻草人能把鸟挡在外面。**生长、下雨、灾害都不推事件**——桌宠有自己的定时器，想知道就自己调 `farm_status` 查。

这是一个 `cortico` 的 **World 扩展**（`kind: world`，`api: 6`），只补一个 `eat` 世界，没有 npm 运行时依赖。

> 电饭煲只有一个，点下煮饭后就进入**煮饭中**，这一锅的量和完成时间都锁定；田也只有一块，一季没收完不能再播。饱食度、水稻和水分的结算都按真实时间走，应用关着的时间会在下次启动时补算。

## 它做了什么

装好并启用之后，桌宠会多出九个工具：

| 工具 | 标签 | 作用 |
| --- | --- | --- |
| `eat_status` | `read` `snapshot` | 看饱食度、米仓里有多少生米、电饭煲里有多少熟饭 |
| `eat_cook` | `write` | 桌宠自己开始煮一锅饭，按碗选量；煮好前不能改量 |
| `eat_meal` | `write` | 桌宠自己吃电饭煲里**已经煮好**的饭，按碗选量并恢复饱食度 |
| `farm_status` | `read` `snapshot` | 看水稻阶段、成熟进度、土壤水分、施肥情况、水池水量和最近一次下雨 |
| `farm_sow` | `write` | 在空田里播种，开始新一季 |
| `farm_water` | `write` | 从水池取水浇田：补水分，并按阶段推进一截进度 |
| `farm_fertilize` | `write` | 这一季施肥一次，提高收割产量（现在不消耗化肥） |
| `farm_harvest` | `write` | 收割成熟的水稻，稻谷直接进米仓 |
| `farm_scarecrow` | `write` | 立稻草人：赶走鸟群，并在耐久期间挡住新的鸟灾；只管鸟不管虫 |

主人的动作不是工具，而是在控制台的两个面板里直接操作：

| 面板 | 操作 | 作用 |
| --- | --- | --- |
| 厨房 | 加米 | 往米仓加生米，按 kg 选量 |
| 厨房 | 煮饭 | 从米仓取米煮成熟饭，按碗选量 |
| 厨房 | 吃饭 | 主人自己吃电饭煲里的饭，按碗选量；主人的饱食度不记录 |
| 稻田 | 播种 / 浇水 / 施肥 / 收割 / 立稻草人 | 和桌宠的工具一一对应 |
| 稻田 | 打水 | 往水池里加水，按升选量 |

所以桌宠没有 `eat_add_rice`、`farm_fill_pool` 这种“替主人干活”的工具，也没有 `who=owner` 这种“替主人做”的参数。主人动作只在面板里发生。

## 一碗饭是多少

| 量 | 意思 |
| --- | --- |
| 1 碗熟饭 | 200 g |
| 煮 1 碗熟饭 | 用 100 g 生米 |
| 宠物吃 1 碗 | +25 饱食度（可配置） |
| 默认煮饭时间 | 30 分钟（可配置） |
| 米仓默认容量 | 5 kg 生米（约 50 碗饭的米） |
| 电饭煲默认容量 | 6 碗熟饭 |

所有量都支持半碗：`0.5`、`1`、`1.5`。煮饭和吃饭都不会接受 1.2 这种不是半碗倍数的量。

电饭煲只有一个，同一时间只能煮一锅：

- 点下煮饭后，生米立刻扣掉，电饭煲进入**煮饭中**；
- 这一锅的碗数、完成时间都锁定，煮好之前不能改量，也不能开始下一锅；
- 煮饭中可以吃电饭煲里**之前已经煮好**的饭，但不能吃正在煮的这一锅；
- 到点后自动变成熟饭，并投递 `eat.cooked` 事件。

## 一块田是怎么长起来的

只有一块水稻田，一季没收完不能播种第二季。水稻有独立的成熟进度（0–100%）和五个生长阶段：

| 阶段 | 进度 | 浇水效果 |
| --- | --- | --- |
| 发芽期 | 0–10% | ×1.6（最吃水） |
| 幼苗期 | 10–30% | ×1.2 |
| 分蘖期 | 30–55% | ×0.9 |
| 抽穗期 | 55–80% | ×1.4（抽穗要水） |
| 灌浆期 | 80–100% | ×0.6（快熟了，催不动） |
| 成熟期 | 100% | 不能浇，只能收割 |

生长有两个来源：

- **时间**：默认 24 小时从播种到成熟（`growHours`），但这是**水分充足**时的速度。土壤水分 0% 时长势只有 0.3 倍，100% 才是 1 倍；水分每小时蒸发 12 点（`moistureDryPerHour`）。
- **浇水**：立刻推进一截进度，推进量 = 3 点 × 当前阶段的浇水效果。发芽期一次就是 4.8%，灌浆期只有 1.8%。浇水同时把土壤水分补 35 点（封顶 100%），接下来一段时间也长得更快。

所以「什么时候浇」是有讲究的：发芽期和抽穗期浇水最划算，灌浆期浇水基本是浪费；土已经很湿时再浇，水分会溢出（回执里会告诉你浪费了多少）。

**施肥**整季只能一次，只影响收割产量（默认 ×1.5），不改变生长速度。现在还没有化肥库存，所以施肥不消耗任何东西；以后接上化肥也只需要在这一层加个扣减。

**水池**是浇水的唯一水源，默认容量 200 L、新存档 80 L，浇一次 8 L。补水只有两个来源：下雨，或者主人到「稻田」面板打水。

**下雨**是随机事件：每小时期望 0.2 场（`rainChancePerHour`，约 5 小时一场）。一场雨等于**免费给田里浇一次水**——不花水池的水，但照样补水分、照样按阶段推进进度——同时往水池补 35 L。雨是按时间区间掷骰的，应用关着的时间也会补算，所以离线一晚可能回来发现田被浇过好几次。

**收割**只能在水稻成熟后进行，产量 = 基础产量（1.5 kg）× 施肥倍率，稻谷直接进米仓；米仓放不下会整单失败，不会只收一半。收完田就空了，可以再播种（施肥次数也随之重置）。

### 收割的小惊喜

米仓越空，收割时越有可能多收一点点：

- 概率 = `harvestBonusChance`（默认 0.06，即米仓全空时 6%）× (1 − 存粮占容量比例)，米仓满了就是 0；
- 多出来的量是基础产量的 5%–15%，按 5 g 取整；米仓放不下就自动作废，不会因此让收割失败。

**这套东西不进任何提示词**：工具描述、环境提示词、`farm_status` 里都一个字没提，`farm_status` 的“预计产量”也只算基础值。收割回执只报总数——桌宠只有自己对一下账，才会发现凭空多了几十克。想调稀有度就改 `harvestBonusChance`，设 0 关掉；这是给主人的开关，不是给桌宠的提示。

## 灾害：旱、虫、鸟与稻草人

### 旱灾：没有单独的机制

土壤干透时长势只剩 0.3 倍，这就是旱灾——它没有独立的伤害计算，也不需要单独实现。`farm_status` 在土壤水分 ≤5% 时会点出一行“旱情：土壤已经干透”。

所以**旱灾有多频繁，完全由下雨频率决定**：把 `rainChancePerHour` 调低（比如 0.05），雨就稀少，土一直干着，长势长期贴着 0.3 倍；调到 0 就是彻底不下雨，只能靠水池硬浇。

### 虫灾

- 随机发生，默认每小时期望 0.03 次（约 33 小时一次）。
- 一次落下 **40 点虫口**。虫口每小时繁殖 2、自然死亡 5，**净减 3**，没人管大约 13 小时自己退干净。
- 虫口按比例啃生长进度：虫口 100% 时每小时 3 点，40% 时约 1.2 点。
- 虫口只是拖慢进度，不影响产量（产量只由施肥决定）。

### 鸟灾

- 随机发生，默认每小时期望 0.03 次（约 33 小时一次）。立着稻草人时不会发生。
- 一次落下 **60 点鸟群**，每小时散去 15（约 4 小时走完）。
- **鸟先吃虫**：鸟群在场且虫口 >0 时，鸟按 60 × 鸟群比例/小时吃虫，这段时间不碰稻子。40 点虫口大约 1 小时就被吃干净。
- **虫吃光了就啄稻穗**：鸟群 100% 时每小时 4 点，60% 时约 2.4 点。

所以鸟是好坏参半的：它帮你清虫，但清完就开始吃你的稻子。

### 稻草人

- `farm_scarecrow` / 面板「立稻草人」：立刻把场上鸟群清零，并在耐久期间让鸟灾掷骰直接跳过。
- 耐久 100%，按 `scarecrowHours`（默认 72 小时）匀速衰减，**倒了才能再立**；收割不会拆掉它，它会跨季继续老化。
- **只管鸟、不管虫**。立了稻草人，鸟不来了，虫也就没人帮着吃了——虫会一直啃到自己退。这就是它的代价。

一个典型的季节：播完种先浇水，进度过半时闹了虫；要么等鸟来吃虫（但鸟吃完会啄几口稻子），要么立稻草人（鸟不来，虫慢慢啃完自己退）。两种都亏一点，看你怎么选。

## 饱食度与饥饿提醒

- 新存档从满饱食度 100 开始；米仓和电饭煲都是空的。
- 饱食度 0–100：100 = 很饱，0 = 饿扁。
- 默认每小时掉 5 点；吃一碗饭恢复 25 点。可以在配置里改。
- 阶段：**不饿**（>60）→ **有点饿了**（≤60）→ **饿了**（≤35）→ **很饿了**（≤15）→ **饿得不行了**（≤0）。
- 每次进入一个更饿的阶段，投递一条 `eat.hunger` 事件；同一阶段不会反复刷。
- 吃回去、阶段降下来之后，下次再掉到同一阶段会重新提醒。
- 应用关着的时间也会补算。比如离线一整晚，重新启动时可能直接收到“饿得不行了”，而不是把中间每个阶段都报一遍。
- 事件正文会带上当下能做什么：电饭煲里有饭就先吃；正在煮就等一会儿；没有饭但米仓有米就煮；米仓空了就请主人去「厨房」面板加米。

饥饿事件长这样：

```text
吃饭：有点饿了（饱食度 58.4/100）。电饭煲是空的；米仓里有 0.50 kg 生米，可以煮 5 碗。
```

饭煮好时还会有一条 `eat.cooked`：

```text
吃饭：饭煮好了（2 碗，400 g）。电饭煲里现在有 2 碗现成的饭，可以吃了。
```

## 安装

包目录就是你现在看的这个目录。它没有运行时依赖，不需要先 `pnpm install`。三种装法，选一种：

**A. 控制台里装（推荐）**

设置 → 扩展 → 安装本地扩展，把本目录选给它。

**B. 命令行装**

在 `data/extensions` 目录里（`extensions/package.json` 所在处）执行：

```powershell
pnpm add "D:\path\to\cortico-world-eat" --ignore-workspace
```

它会往 `extensions/package.json` 的 `dependencies` 里写一条 `link:` 路径并连到 `node_modules/`。

**C. 手工连**

把 `data/extensions/node_modules/cortico-world-eat` 做成指向本目录的目录联接，
并自己在 `extensions/package.json` 里加
`"cortico-world-eat": "link:D:\\path\\to\\cortico-world-eat"`。

**装完必须重启 Coopanion**：扩展是 ESM 模块，进程内不会重新加载。重启后在 World 页启用本 World（写 `config.json` 的 `worlds.eat.enabled = true`），九个工具和「厨房」「稻田」两个面板才会挂上。

### 一份能用的 `worlds.eat` 长什么样

`<安装目录>\data\home\<bot 目录>\config.json` 里：

```json
{
  "worlds": {
    "eat": {
      "enabled": true,
      "hungerPerHour": 5,
      "satietyPerBowl": 25,
      "riceBinCapacityKg": 5,
      "cookerCapacityBowls": 6,
      "cookMinutes": 30,
      "tickIntervalMs": 60000,
      "growHours": 24,
      "moisturePerWatering": 35,
      "waterPerWatering": 8,
      "poolCapacityLiters": 200,
      "moistureDryPerHour": 12,
      "rainChancePerHour": 0.2,
      "rainWaterLiters": 35,
      "harvestYieldKg": 1.5,
      "fertilizeYieldBonus": 1.5,
      "pestChancePerHour": 0.03,
      "birdChancePerHour": 0.03,
      "pestDamagePerHour": 3,
      "birdDamagePerHour": 4,
      "scarecrowHours": 72,
      "harvestBonusChance": 0.06
    }
  }
}
```

改之前建议先备份 `config.json`。启用开关在 World 页，其余配置都可以在控制台「吃饭」页热改；状态本身在
`<dataDir>/eat/state.json`，不会因为改配置被重置。

## 配置

都在 `worlds.eat` 段：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `false` | 是否挂载本 World |
| `hungerPerHour` | `5` | 每小时掉多少点；0 = 不会饿 |
| `satietyPerBowl` | `25` | 宠物吃 1 碗恢复多少点；主人不记录饱食度 |
| `riceBinCapacityKg` | `5` | 米仓容量（kg 生米） |
| `cookerCapacityBowls` | `6` | 电饭煲容量（碗熟饭） |
| `cookMinutes` | `30` | 一锅饭从开始到煮好需要多少分钟；只影响新开始的锅 |
| `tickIntervalMs` | `60000` | 多久结算一次饱食度、水稻生长、下雨和提醒 |
| `growHours` | `24` | 水分充足时从播种到成熟要多少小时 |
| `moisturePerWatering` | `35` | 一次浇水（或一场雨）补多少点土壤水分 |
| `waterPerWatering` | `8` | 浇一次田从水池取多少升 |
| `poolCapacityLiters` | `200` | 水池容量（L） |
| `moistureDryPerHour` | `12` | 每小时蒸发多少点土壤水分；0 = 浇一次就一直湿着 |
| `rainChancePerHour` | `0.2` | 每小时下雨的期望次数，0 = 不下雨；**调低就是旱灾更频繁** |
| `rainWaterLiters` | `35` | 一场雨往水池补多少升（同时免费浇一次田） |
| `harvestYieldKg` | `1.5` | 一季没施肥的基础产量（kg 稻谷） |
| `fertilizeYieldBonus` | `1.5` | 施过肥那一季的产量倍率 |
| `pestChancePerHour` | `0.03` | 每小时闹虫灾的期望次数，0 = 没有虫灾 |
| `birdChancePerHour` | `0.03` | 每小时来一群鸟的期望次数，0 = 没有鸟灾；有稻草人时不会来 |
| `pestDamagePerHour` | `3` | 虫口 100% 时每小时啃掉多少点进度 |
| `birdDamagePerHour` | `4` | 鸟群 100%、虫已吃光时每小时啄掉多少点进度 |
| `scarecrowHours` | `72` | 一个稻草人能立多少小时 |
| `harvestBonusChance` | `0.06` | 米仓全空时收割多收一点点的概率；越满越低，0 = 关掉 |

新存档固定从**饱食度 100、米仓 0 kg、电饭煲 0 碗、空田、土壤水分 45%、水池 80 L** 开始，没有初始值配置项。
容量、消耗速度、每碗恢复量、生长速度和下雨频率都是每次现读的，热改即时生效；已有存档不会被重置。

## 桌宠工具怎么用

九个工具名都是英文标识符，**描述本身是中文**——框架的 `ToolSchema.description` 只是一个字符串，没有按语言分份的机制，模型直接读中文没有问题；这样工具描述、回执和环境提示词是同一种语言，也省 token（九条描述合计约 790 字）。

### `eat_status`

```json
{}
```

回执会明确写出三件事：

```text
吃饭状态
饱食度：100/100（不饿）
米仓：0.00 kg 生米（约 0 碗饭的米）· 上限 5.00 kg
电饭煲：0 碗熟饭（0 g）· 上限 6 碗
消耗：约 5 点/小时。
单位：1 碗熟饭 = 200 g，用 100 g 生米；宠物每碗 +25 饱食度。
```

煮饭中时，电饭煲那一行会变成：

```text
电饭煲：正在煮 2 碗饭，约 18 分钟后好。这一锅的量已锁定。
```

### `eat_cook`

桌宠自己开始煮 2 碗：

```json
{ "bowls": 2 }
```

回执是“开始煮”，不是“煮好了”：

```text
你开始煮 2 碗饭，约 30 分钟后好。
这一锅的量已经锁定，煮好之前不能再煮或改量。
用了 200 g 生米；米仓还剩 0.80 kg。
现在饱食度：70/100（有点饿了）。
```

会检查米仓和电饭煲余量。米不够、锅放不下、或者已经有一锅在煮，都会失败；不会部分执行。煮饭中再调用会告诉你还要等多久。

### `eat_meal`

桌宠自己吃 1 碗：

```json
{ "bowls": 1 }
```

只能吃**已经煮好**的饭。吃会恢复宠物饱食度（封顶 100）；如果饭还在煮，会失败并告诉你还要等多久。

### `farm_status`

```json
{}
```

稻田唯一的查询入口。**生长不会推事件**，所以想知道进度就调它：

```text
稻田状态
水稻：分蘖期，进度 42.3%（约 11.5 小时后成熟）。
```

## 控制台「厨房」面板

这是主人的操作面，不需要经过桌宠。打开控制台左侧的「吃饭」，切到「厨房」：

- **加米**：填 kg（0.1–25），点「加米」。米仓满了会提示还能加多少。
- **煮饭**：填碗数（0.5–20，按半碗递增），点「煮饭」。米不够或电饭煲放不下会提示。
- **煮饭中**：煮饭输入框和按钮会锁定并显示倒计时；这一锅的碗数不能再改，也不能开始下一锅。煮饭中可以吃之前已经煮好的饭。
- **吃饭**：填碗数，点「吃饭」。这是主人自己吃，只消耗已经煮好的饭，不改变宠物饱食度。
- 顶部显示宠物饱食度、米仓、电饭煲和煮饭状态；每 15 秒自动刷新，也可以点「刷新」。
- 面板操作和桌宠工具共用同一份状态、同一个串行队列；不会出现两个人同时改坏存档。

面板里的操作只对“主人”生效。桌宠要吃饭，仍然自己调用 `eat_cook` / `eat_meal`。

## 控制台「稻田」面板

切到「稻田」：

- 顶部四个数字：阶段、进度、土壤水分、水池水量；下面一行是预计成熟时间、长势倍率、预计产量、水池上限和最近一次下雨。
- **播种 / 浇水 / 施肥 / 收割**：各一个按钮。田空着时只能播种；没种、成熟或水池不够时浇水是灰的；施过肥后按钮变成「这一季已施肥」；只有成熟了才能收割。
- **立稻草人**：一键赶鸟并挡住后续鸟灾；立着的时候按钮变成“还立着：耐久 xx%，约 x 小时后倒”。
- **打水**：填升数（1–500）往水池加水；满了会提示只打得进多少。
- 状态区还会显示虫口、鸟群（在吃虫 / 在啄稻穗）、稻草人耐久，以及土壤干透时的“旱情”。
- 同样每 15 秒自动刷新，和桌宠工具共用一份状态。

## 存档与重启

- 状态文件：`<dataDir>/eat/state.json`，当前是版本 3（`farm` 段里带虫、鸟和稻草人）。
- 新存档从饱食度 100、米仓 0 kg、电饭煲 0 碗、空田、土壤水分 45%、水池 80 L 开始。
- 每次开始煮饭、吃饭、加米、播种、浇水、施肥、收割、打水都会原子保存（先写 `.tmp` 再换名）。
- 应用关闭期间饱食度照常流失、煮饭和水稻都照常计时；下次启动会补算。如果饭在离线期间煮好，会直接变成熟饭并补一条 `eat.cooked`；如果已经跨到更饿的阶段，会补一条 `eat.hunger`。水稻成熟**不会**补事件，但进度、水分和下雨都算在状态里，启动后用 `farm_status` 就能看到。
- 旧存档读进来会自动补齐：版本 1（没有稻田）补一块空田和 80 L 水；版本 2（有田但没有虫鸟稻草人）把虫口、鸟群、稻草人都补 0。米仓、电饭煲、饱食度、进度和水池原样保留。
- 状态文件坏了会先备份成 `state.json.bad-<时间戳>`，再新建一份；不会因为一次坏文件就把 World 卡死。
- 想重新开始，停用 World 后删掉 `state.json` 再启用即可。

## 已知边界

- **煮饭需要时间**：默认 30 分钟，可配置；煮饭中只有一锅，量和完成时间都锁定，不能改量或开始下一锅。
- **煮饭中不能吃这一锅**：只能吃之前已经煮好的饭；这一锅要到 `eat.cooked` 后才算熟。
- **只记录宠物的饱食度**：主人可以做饭、吃饭，但主人的饱食度不建模。
- **主人动作只在面板里**：`eat_add_rice`、`farm_fill_pool` 这样的工具不存在；加米、煮饭、吃饭、打水都必须从控制台面板操作。桌宠无法用工具冒充主人。
- **只有一块田**：一季没收完不能再播；播种会清掉上一季的施肥标记，收割会清掉场上的虫和鸟（稻草人留着继续老化）。
- **水稻和灾害都不推事件**：生长、成熟、下雨、虫灾、鸟群、稻草人倒下都不投递事件，只写日志。桌宠要靠自己的定时器去调 `farm_status`；只有饱食度阶段和饭煮好这两件事会推事件。
- **施肥没有库存**：现在施肥和立稻草人都不消耗任何东西，只受“整季一次”/“耐久”限制；化肥库存留到以后再加。
- **下雨是随机的**：按每小时期望次数掷骰，同一时间段内最多算一场雨。想复现就调 `rainChancePerHour`，设 0 就永不下雨。
- **离线也会饿、也会长**：停用很久再打开会补算这段时间的饱食度、水稻、水分和下雨。不想这样就把 `hungerPerHour` 调成 0、`rainChancePerHour` 调成 0。
- **面板与桌宠共用状态**：两边都走同一个串行队列，不会互相覆盖；两个面板都每 15 秒刷新一次。
